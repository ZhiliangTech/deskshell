# 项目决策记录与待确定事项

更新日期：2026-10-31。项目入口：[方向与设计总览](../../PROJECT.md)。

“已确认”表示产品或研究方向已在讨论中达成一致；“工程默认”表示当前据此准备实现、仍可依据证据调整；“待确定”表示需要选择或测量。研究方向已确认不等于研究假设成立，RFC 仍为 Draft 不等于产品方向未定。

## 已确认的方向与原则

| 编号 | 决定 | 适用范围与依据 |
| --- | --- | --- |
| D01 | 以本地模型和智能体组织个人计算 | 长期愿景是硬件承载智能体，由系统管理任务与资源 |
| D02 | 第一阶段交付运行在现有 Windows 电脑上的智能体系统 | 宿主和执行在本机，当前模型推理在云端；专用设备和系统发行版后置 |
| D03 | 在 deskshell 现有工程上演进 | 复用执行内核、协议、技能、驱动、CLI、MCP 和桌面入口 |
| D04 | 模型提案与可信执行、审批分离 | 模型不自行签发授权；任务完成以实际目标验证为准 |
| D05 | 预览绑定固定计划，持久记录任务，明确恢复边界 | 第一阶段工程路线；具体接口和存储格式见 RFC 0001 草案 |
| D06 | 当前使用国产云端大模型 API，长期面向本地模型 | 维护者已澄清当前推理形态；模型可替换，供应商切换与数据外发范围由宿主配置管理 |
| D07 | 第一阶段使用审阅过的第一方技能 | 当前 TypeScript 技能是受信代码，第三方沙箱属于后续能力 |
| D08 | 采用 G1–G5 的阶段顺序 | G1–G4 共同形成第一阶段用户产品；阶段不代表工期承诺 |
| D09 | 研究主线为有身份、版本与约束的语义资源视图 | 已同意研究方向，收益尚待同条件对照实验 |
| D10 | 研究效果凭据与选择性恢复，支撑可信状态变化 | 已同意研究方向，先限制到可观测、可核查的原语 |
| D11 | 研究效果必须通过公平实验判断 | 当前固定云端供应商、模型配置、工具、授权与预算；本地复验再固定推理硬件；拒绝和完成分开统计 |
| D12 | 首个真实应用选择 Windows 记事本 | 维护者委托选择后，工程侧选定；版本与控件行为仍需实测，见[应用方案](first-application.md) |

RFC 的具体字段、原语集合、数据库依赖与实验参数仍需工程评审；本表不把这些细节自动标为 Accepted。协议变更按[现有 RFC 流程](../../rfcs/README.md)记录。

Q08 的 TaskRequest、TaskResult、固定计划、执行认领和照片组合验证已在新 agent 服务落实。取消保留已产生效果；普通撤销和中断核查使用单独 RecoveryPlan、摘要批准及唯一认领，未核验的新对象拒绝猜归属；旧入口仍需迁移。真实目录、云端外发、开机启动和长期委托分别配置，当前未注册开机启动。程序不自动发送本地文件名、hash 或正文，输入目标文本自身会发送。操作及限制见[文件任务](agent-file-task.md)与[恢复说明](task-recovery.md)。

应用会话在同一精确授权内连续推进 `open/edit/save-copy`，每轮重新观察与验证，模型不能修改已固定的路径或正文。真实 DeepSeek 配合合成编辑器已完成三轮；固定原生计划另在完整服务链通过 CRLF/LF 两次验收。早期两次人工输入守卫拒绝另计；后续本地合成规划和真实 DeepSeek 均在原生链完成三轮，四类故障保护通过。真实原生三轮为 2,543 token、估算 0.0038316 USD（非账单）。默认生产服务已独立复验，并在新输入前拒绝第二任务；仍不提供应用 Undo。早期 Computer Use 的 accessibility 为 null 是工具读取缺口，不再作为记事本缺少可访问性的依据。详见[多轮任务](autonomous-tasks.md)与[首个应用](first-application.md)。

首场景明确使用文件修改时间和上海时区，不解释为拍摄时间。旧 [dedupe-folders](../../packages/skills/dedupe-folders/index.ts) 的大文件前缀指纹不能证明完整重复；新的[照片组合技能](../../packages/runtime/src/photo-task.ts) 独立采用完整内容筛选及逐字节比较、固定保留规则和 `_duplicates` 目录，并将这些条件纳入本地可信目标验证。

### 当前开发机的已观察条件

2026-10-31 通过 Windows CIM 读取：Windows 11 专业版 64 位，系统版本 `10.0.26200`；AMD Ryzen 7 9700X，8 核 16 线程；操作系统报告总内存约 47.2 GiB；可见 NVIDIA GeForce RTX 5080 和 AMD Radeon 集成显卡，另有虚拟显示适配器。

这些信息只描述本次开发环境。当前云端原型不以 GPU 配置作为接入条件；尚未测量本地模型加载后的可用显存、峰值内存、吞吐和端到端延迟，不能据此推导未来本地模型的推荐配置。

### 实验前必须固定的内容

每次正式对照实验登记代码版本、资源协议版本、供应商与端点、请求模型/返回标识、调用时间、思考与采样参数、客户端环境、工具集合、授权、预算、测试集划分、重复次数和评价脚本。云端硬件与服务版本的不可控变化如实标注，交错配对运行减少时间偏差；本地复验另登记模型文件、量化、后端与推理硬件。调试集与留出验证集分开。

质量、错误对象操作、过期观察错误、推理消耗、延迟、拒绝、误报完成及恢复结果分别报告。零残留不能替代任务成功率；没有执行的拒绝任务也不能算作成功完成。人工修改保护与冲突判断需要由独立的真实状态检查验证。

安全与记账不变量的已定义用例必须全部通过；模型质量和性能阈值待基线测量后登记。尚无“降低多少 token”“提升多少成功率”等已验证数字。

## 后续阶段再决定

本地模型选型与最低硬件、第三方扩展市场、跨平台产品放行标准、外部 MCP 工具写入、委托式长期自动执行、专用设备、系统发行版和商业交付方式，分别在有对应需求与证据时决定。当前继续按国产云端推理、第一方技能、受限任务和明确授权的产品路径推进。
