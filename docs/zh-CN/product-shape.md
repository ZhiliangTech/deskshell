# 产品形态提案：从"给 agent 用的运行时"改成"住在我电脑里的同事"

> 状态：**提案，未采纳**。写于 2026-11-01。采纳与否是维护者的决定，采纳意味着 README、路线图、对外叙事全部重写，内核降为内部件。
> 参照对象：OpenClaw（原 Clawdbot / Moltbot）。它用四个产品决定改变了品类，而不是用技术。

## 一句话定义

> 一个常驻在我电脑上、通过聊天软件跟我说话、有长期记忆、能真的替我干活的助手——它做的每件事都进账本，任何一步我都能撤回。

与现在的差别：现在的 deskshell 是"别人写 agent 时用的执行层"；这个版本是"人直接用的助手，执行层藏在里面"。

## OpenClaw 到底改了什么（四个决定，逐条对照）

| 决定 | OpenClaw 的做法 | 我们现在有什么 | 必须补什么 |
| --- | --- | --- | --- |
| **入口** | 住进用户已有的聊天软件（Telegram / Discord / WhatsApp），零新 UI | CLI + MCP + 半成品桌面面板 | 选**一个** IM 做入口（Telegram bot 最便宜：有推送、有历史、有身份、零安装） |
| **存在方式** | 常驻 + 本地持久分层记忆，用得越久越懂你 | 常驻宿主有，记忆只有任务历史 | 可编辑的记忆文件（markdown）+ SQLite 索引；用户能看、能改、能删 |
| **权限** | 直接给系统级权限（shell、文件，甚至 sudo），换来能力上限 | 能力声明 + 审批 + 撤销（**反向**：把权限收紧了） | 权限模型保留，但要能从"每步审批"退化成"一次授权、事后可查可撤" |
| **默认体验** | 开箱有人格、有主动性，不是空壳 | 开箱是一个命令列表 | 默认人设 + 主动汇报（每天一句话：我今天干了什么） |

结论很直接：**照抄 OpenClaw，你会得到一个"更安全但更弱"的 OpenClaw，没人要。** 安全不是它的卖点，能力+人格+零摩擦才是。

## 唯一空位：把"能撤回"做成能力放大器，而不是合规附件

OpenClaw 这类产品证明了两件事：需求是真的（24 万 star 级别），结构性缺陷也是真的——**给了系统权限，但没有可核查的账本和真正的回滚**，出事只能靠用户自己收拾。

所以差异化的逻辑必须是这样闭环的：

```
能撤回  →  敢给更大权限  →  能真正完成任务  →  用户离不开
   ↑                                              │
   └──────────── 每次任务都有账本 ────────────────┘
```

注意顺序：**先有能力，最后才是账本**。如果先做账本，就得到一个"没人用的安全产品"——那正是我们现在的位置。

## 两周可验证里程碑（不许加功能）

| 时间 | 交付 | 判据 |
| --- | --- | --- |
| 第 1 周 | Telegram bot + 本机宿主；能完成 3 类真实任务（整理目录、批量改名、生成或修改表格），全部走账本 | 每类任务连续跑 5 次不失败；失败时留下现场且能说清哪一步 |
| 第 2 周 | `/undo` 撤回最近一次任务并逐字节验证；`/log` 用一句人话说明今天干了什么 | 撤回后目录哈希与执行前一致；`/log` 不需要看 JSON 就能读懂 |
| 判据 | 自己连续用 7 天不关；1 个朋友用满 3 天且没卸载 | 两个都成立才继续；否则回到"作品集路线" |

## 一人项目的三条硬约束

1. **不正面竞争**。OpenClaw 已有社区、基金会、插件生态。你的位置只能是"某类人 + 某个场景"，不是"更好的 OpenClaw"。
2. **胜负在第一次 60 秒和第 7 天**，不在功能数量。第一句话它得听懂并做成一件小事；第七天它得记得你上周说过什么。
3. **权限越大，账本越要前置**。给 shell、给文件写权限的产品，一旦出事就是数据事故；你的账本不是合规装饰，是让用户敢授权的前提。
