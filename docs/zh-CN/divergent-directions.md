# 发散：十个被默认的前提，反过来会怎样

> 写于 2026-11-01。**不是路线图，是可以被砍掉的候选**。用途：当"下一阶段"这个词变得空转时，回来挑一条真的能做的。
> 方法：发散不是加功能，是改前提。每条都要过三道筛——模型强 10 倍后还成立吗？一个人做得出来吗？它换的是单位还是功能？

## 0. 三道筛（先立规矩，不然发散会变成许愿）

| 筛子 | 问题 | 为什么 |
| --- | --- | --- |
| 抗能力增长 | 模型强 10 倍之后，这条还重要吗？ | 关于"能力"的想法会被下一代模型抹平；关于"责任、状态、可逆"的想法不会 |
| 一人可做 | 不依赖生态、渠道、资本，一个人 3 个月能做出可验证的一小块吗？ | 否则只是把失败原因外包给环境 |
| 换单位不换功能 | 它改变的是"交互的最小单位"，还是给现有产品加一个开关？ | 加开关的是迭代，换单位的是阶段 |

## 1. 撤销 = 重放，不是逆操作

**前提**：撤销要每个动作自己写"怎么退回去"。
**反过来**：把执行记录当成一段事件流，撤回 = 从初始状态重放前 N 步；无法重放的外部副作用，用补偿事程单独标记。

- 机制价值：正确性由"重放器"统一保证，而不是 N 个手写的 undo。**新增一种动作，不需要写 undo 也能被正确撤回。**
- 直接治的病：我们刚修的那一批 bug（noop 占位、无指纹覆盖、轮转丢历史）全都是"每个动作各自保证撤销"这个结构的必然产物。
- 检验：加一个新动作类型，撤销测试不改一行仍然通过。

## 2. 预演账本：批准的是"一段可能的历史"，不是一条命令

**前提**：先下命令，再看结果。
**反过来**：执行前先生成"如果执行，账本会长这样"——包含失败分支、残留点、不可逆点、需要多久。人批准的是**这段可能的历史**。

- 机制价值：把"确认对话框"升级成"世界线选择"。人可以看见"如果第三步失败会留下什么"，而不是等它发生。
- 检验：用户能在 3 秒内回答"这次会留下什么"，并且能在批准前换一条分支。

## 3. 影子身体：agent 不该和我抢同一个身体

**前提**：agent 借用我的电脑，所以它和我共用同一个真实世界。
**反过来**：给 agent 一个隔离的影子身体（影子文件系统 + 影子窗口 + 影子网络），它在里面干活，完成后把 **diff** 提交到真实世界。"撤销" = 丢弃影子。

- 机制价值：**"失败无残留"从努力目标变成默认值**。它可以并行试三种方案，只有一种落地。
- 一个人做得出来：Windows Sandbox / 快照 VM / 容器 + 影子目录，不需要惊天发明。
- 检验：同一个任务让 agent 试三种做法，真实目录在执行前后哈希不变。

## 4. 记忆 = 可执行规则，不是上下文

**前提**：记忆是"它记得我说过什么"。
**反过来**：每次纠正都被编译成一条**带作用域、到期时间、例外**的规则；记忆是"我个人的法律"，可读、可审、可撤、可导出。

- 机制价值：换模型、换 agent、换机器，规则还在——因为规则不在模型里。这才是"越用越懂你"的结构性实现，而不是向量检索更像你。
- 检验：换一个完全不同的 agent，装进同一份规则，它的行为符合你的偏好。

## 5. 渐进授权：权限是坡度，不是开关

**前提**：权限是"授予/不授予"。
**反过来**：权限随连续成功增长、随异常自动收缩。第一次做某类任务要逐步批准，第十次只需要事后汇报；出现一次异常，坡度回落。

- 机制价值：把"要不要信任它"从一次性赌博变成连续调节。
- 检验：同一类任务，第 10 次的审批界面比第 1 次短，而异常时立刻变长。

## 6. 账本给机器看：效果证明

**前提**：账本给人审计，人看完点确定。
**反过来**：账本变成机器可验证的证明（proof of effect），别的 agent、保险、合规系统可以**自动**读懂"谁授权、做了什么、能否撤回、依据是什么"。

- 机制价值：审计从人工变成协议；也是"agent 之间互相调用"的前提。
- 检验：第三方只读账本就能判定一次操作是否合规，不需要问人。

## 7. 智能下沉到环境：事务性 OS

**前提**：让 agent 更小心。
**反过来**：让环境更宽容——文件系统知道自己被谁改过，应用知道自己被谁操作过，系统提供"事务"原语；agent 只声明意图，剩下的由环境保证。

- 机制价值：这是 GUI 赢的方式（不是让用户更聪明，而是让环境更宽容：可见即可得、撤销栈）。如果这条成立，**"内核"才是对的那一层**，而不是包袱。
- 检验：换一个更笨的模型，残留率不变。

## 8. 共同编辑世界状态，而不是对话

**前提**：人机交互是"我说，它做"。
**反过来**：人和 agent 共同编辑同一份状态（文件树、日程、任务板），对话只是批注。就像多人协作文档，但对象是"我的电脑状态"。

- 机制价值：**"它没听懂"这一整类问题消失**——因为双方看的是同一个对象，不是各自的措辞。
- 检验：用户不再需要用"我说过了"来纠正它。

## 9. agent 之间的抵押与保险

**前提**：agent 之间靠 API key 互相调用。
**反过来**：调用时要抵押资源（预算、信誉、回滚能力），出错按抵押赔付。

- 机制价值：给 agent 经济补上"责任"这个维度——现在 agent 之间只有能力，没有责任。
- 检验：出现争议时"谁负责"能被自动判定，而不是靠人吵。

## 10. agent 的节律：睡眠与晨报

**前提**：agent 常驻 = 随时待命、随时打断。
**反过来**：它有自己的节律——你不在时做低风险整理，你回来时给一份"昨夜我做了什么 + 今天建议"。

- 机制价值：主动性从"打断"变成"陪伴"；产品的时间结构从"会话"变成"日夜"。
- 检验：用户主动打开的频次下降，但留存和感知价值上升。

## 我会押的三个（结合现在手上的东西）

| 选 | 理由 | 第一个可验证的形态 |
| --- | --- | --- |
| **#1 重放式撤销** | 它是正确性的地基，而且直接消灭"每个动作各写 undo"这一整类 bug；我们刚修的全是这一类 | 把 journal 变成事件流，写一个重放器，跑现有 72 项回归 |
| **#3 影子身体** | 它把"残留"从指标变成非问题；一个人就能做；且和"可撤销"是同一个故事的两面 | 影子目录 + diff 提交，跑"三次尝试只落地一次" |
| **#7 智能下沉** | 它是唯一能让"内核"这一层变成正确赌注的论点，也是唯一不怕模型变强的方向 | 在文件系统层提供事务与来源标记，让一个笨 agent 也不留残留 |

## 我认为大概率是错的三个

- **#6 账本给机器看**：方向对，但要等生态；一个人做只会做出一个没人读的格式。
- **#9 抵押与保险**：需要多主体真实存在，现在只有"一个 agent"；会做出一个空转的经济模型。
- **#10 节律**：很可能是产品装饰——听起来动人，但不改变任何结构，做出来也验证不了。

## 一句话

真正值得发散的方向，都指向同一个问题：**让"出错"这件事在结构上变得廉价**——不是让 agent 更聪明，而是让世界更能容忍它不聪明。
