# 个人计算的第四层：状态与因果

> 写于 2026-11-01。这不是路线图，是**主张**——项目如果只留一句话，留这句。
> 与 [stage-thesis.md](stage-thesis.md)（阶段）和 [product-doctrine.md](product-doctrine.md)（纪律）配套：这份讲**我们在哪一层上做东西**。

## 一、今天个人计算机只有三层，缺第四层

| 层 | 管什么 | 什么时候有的 | 不管什么 |
| --- | --- | --- | --- |
| 文件系统 | 字节的存放与命名 | 1970s | 不理解内容，不记历史，不记谁改的 |
| 数据库 | 结构化数据 + 事务 | 1970s | 只管自己的库，管不到你的文件和桌面 |
| 版本控制 | 代码的历史与分支 | 2005 | 只管仓库，不管你的文档、照片、设置、应用状态 |

**个人计算机没有一层在管"整台机器的状态与因果"**：没有时间轴、没有谁改了什么、没有"回到上周三"、没有"这一步能不能撤"。

这不是疏忽。**因为过去只有人改自己的电脑**，人记得自己干了什么，撤销靠手，历史靠备份。需求不存在，层就不长出来。

## 二、agent 让这一层从奢侈品变成必需品

第一次，你的电脑会被**非人主体**改动：不记得自己干了什么、不可靠、会犯错、可能同时有多个。

于是三件事同时变成刚需：

1. **时间**：出事了要知道"什么时候变成这样的"；
2. **因果**：要知道"谁改的、依据什么"；
3. **可逆**：要能只退回那一步，不牵连别的。

今天所有 agent 产品都在用"人盯着屏幕"临时替代这一层——等于用人的注意力当日志。这不是架构，是权宜。

**结论：agent 的普及会逼出个人计算的第四层。谁定义它，谁定义下一代个人计算的底座。**

## 三、第四层由四个原语构成（与 RFC 0003 对齐）

| 原语 | 一句话 | 现状 |
| --- | --- | --- |
| **状态版本**（Checkpoint） | 工作集的可分叉快照，不是整盘备份 | 无 |
| **因果账本**（Effect Ledger） | 每次变化：谁、改了什么、依据什么、能否撤 | **协议 v0 + 两个实现已通过 27/27 一致性测试** |
| **语义身份**（Object） | 一个对象在磁盘/缓冲/窗口/字段里的多重投影 | 无（RFC 0003 有设计） |
| **委托契约**（Delegation） | 权限、预算、期限、例外、复议 | 部分（审批 + 摘要绑定有，长期委托无） |

四者必须同时存在，因为互为坐标系：没有状态版本，账本无法解释差异；没有语义身份，账本记不住"同一个东西"；没有委托，账本无法追责。

## 四、判断这一层是否成立的三条（不是叙事，是验收）

1. **默认集成**：别的 agent 产品把它装进默认路径，而不是"可选插件"。
2. **跨厂商**：A 家的 agent 写的账，B 家的工具能读、能撤。
3. **可被第三方实现**：规范 + 一致性向量存在，且已有**非本仓库**的实现通过。

第三条今天已经迈出第一步（`spec/effect-ledger/v0`，两个独立实现，27/27）。前两条是未来数年的活。

## 五、残酷的现状

按第四层的完整度算，今天大约 **5%**：

- 有：账本语义、逐步撤销、冲突拒绝、协议 + 一致性测试；
- 没有：状态版本、语义身份、长期委托、任何外部依赖者。

**没有外部依赖者，就不是基础设施，是一个写得不错的库。** 这一条不能靠叙事跨过去。

## 六、第一个能被看见的形态：时间轴

不是"任务列表"，是**对象的历史**：

```
$ deskshell timeline ~/Documents/合同.docx
2026-11-01 14:32  agent:relay    改写第 3 段（依据：你批准的指令 a1b2）  ✅ 可撤回
2026-10-31 09:12  你（Word）     保存：+2 段                             —（人改，不在账本）
2026-10-30 18:00  agent:photo    移动到 归档/2026-10/                    ✅ 可撤回
```

它同时演示了第四层的四件事：时间、因果、对象身份、可逆。

**这也是一条验收标准**：如果做不出这个视图，第四层就还只是说法。

## 七、三年内的三个阶段（承诺是阶段，不是日期）

| 阶段 | 目标 | 验收 |
| --- | --- | --- |
| S1（现在–6 个月） | 让账本进入主路径：每一次 agent 执行都产出标准账本；时间轴可查 | 任意对象的完整历史可读；两个实现的向量保持 100% 一致 |
| S2（6–18 个月） | 加上状态版本：工作集快照 + 回到某一刻 | 1 万文件的工作集，恢复到任意时刻 < 5s，且逐字节一致 |
| S3（18 个月+） | 跨主体：多 agent、多厂商共用一套账与一套撤销语义 | 至少一个**外部**实现通过一致性测试 |

## 八、一句话

**文件系统让电脑能存东西，数据库让程序能改东西，版本控制让代码能回退；第四层让"人 + agent 共同使用的电脑"第一次拥有时间、因果和反悔权。**
