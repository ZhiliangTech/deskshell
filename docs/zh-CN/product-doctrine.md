# 产品纪律：内部要严，对外只说结果

> 写于 2026-11-01。起因：项目把"不注册开机启动、默认生产写入禁用、不静默外发"当成卖点讲，但用户不 care 机制，用户只 care 后果。
> 这不是要删掉约束，而是要把约束从**叙事**里拿掉，留在**实现**里。

## 一句话

**约束是纪律，不是卖点；能力是产品，不是风险。**

## 三层，别混

| 层 | 该严还是该松 | 用户看得见吗 |
| --- | --- | --- |
| **内部纪律**（审批、撤销、账本、写入前验证、崩溃不重放） | **尽量严**，越严越好 | 看不见，也不该看见 |
| **对外承诺**（一句话能记住的东西） | **尽量少**，只说后果 | 必须一眼看懂 |
| **产品能力**（能不能干活、是否常驻、能否写真实文件） | **尽量满**，不许被纪律吃掉 | 用户只在乎这个 |

现在的病：把纪律写进了承诺（"我们默认禁用生产写入"），于是纪律变成了能力上限——**产品没法真的干活，却还觉得自己很正派。**

## 审批的门槛由"可逆性"决定，不由"风险等级"决定

这是最重要的一条。现在的实现按"风险/能力"逐步确认，那是开发者思维，用户会直接关掉。

正确的规则只有两条：

1. **能撤回的，一律不问。** 移动、重命名、归档、写副本、生成文件——做完给一句"可以撤回"，不问。
2. **不能撤回的，问一次，且默认拒绝。** 删除、覆盖、外发原文、花钱——一次确认，之后在会话内不再重复问。

推论：**把不可逆动作变成可逆的，比给它加确认更有价值。** 删除 → 移到"待确认区"；覆盖 → 先备份旧版本；外发 → 可撤回的脱敏摘要。每做一次这种转化，就少一次打断。

## 常驻不是风险，是产品属性

"不注册开机启动"解决的是"它在背后干了什么"，但这个问题该由**账本**回答，不该由**不常驻**回答。一个只能用一次的产品，不可能是"用 AI 的人都要用"的东西。

- 常驻 + 开机启动：默认开。
- 它在背后做了什么：随时可查，一句人话。
- 你不想让它跑：一个开关，立即生效。

## 对外只写这三句

1. **它替你做完了什么**（具体动作 + 具体对象）。
2. **做错了怎么办**（一键撤回，逐字节一致）。
3. **你的东西去哪了**（默认不上传；上传什么，账本里有记录）。

不写：架构、协议、能力声明、审批模型、"我们不做 X"。这些是给评审和工程师看的，放在 `STATUS.md` 和 RFC 里。

## 反面清单（看到就删）

- "默认禁用生产写入" → 用户读到的是"它不能干活"。
- "不注册开机启动" → 用户读到的是"每次都要手动开"。
- "不静默外发" → 用户读到的是"每次都要点同意"。
- "能力声明 / 作用域 / 摘要批准" → 用户读到的是"这跟我有什么关系"。
- "如实写、不夸大"（`STATUS.md` 的语气）→ 对外读起来像免责声明。这份文件留内部。

## 一条底线，不能一起松掉

**默认全开的前提是出事能兜住。** 没有任何账本和回滚的产品（比如给 agent 系统权限却只靠"开源可审"）是在赌运气；赌赢一百次，输一次就结束。所以顺序永远是：

```
先把"可撤"做到位 → 再把默认值全开 → 再谈"用 AI 的人都要用"
```

反过来做（先全开、后补账本），就是把用户当测试环境。

## 附：需求定律 —— 价值 ÷ 验证成本

2026-11-01 补。起因：判断"现在人对 agent 的需求其实没那么多"。这个判断是对的，但原因常被说错：不是模型不行，是**验证成本**没被解决。

> **对 AI 的真实需求 ≈ 这件事的价值 ÷ 用户核对它做对没有的成本。**

| 场景 | 价值 | 验证成本 | 结果 |
| --- | --- | --- | --- |
| 聊天、翻译、总结 | 中 | **极低**（读一遍就知道） | 人人都在用 |
| 找东西 | 中 | **极低**（找到没找到一眼看穿） | 人人都在用 |
| 写代码 | 高 | **低**（编译器/测试替你判） | 开发者重度使用 |
| 结构化抽取 | 高 | 低（对 schema） | 企业已落地 |
| **替你整理文件 / 操作软件** | 中 | **高**（要逐个检查两百个文件） | **需求小，且在等一个解法** |

这条定律解释了两个现象：

1. 为什么 agent 在编程和数据抽取里先落地——**判分是机器做的**；
2. 为什么"AI 管家"喊了三年没人真用——**判分是用户做的，而判分和干活一样累**。

推论（可检验）：

- 任何**降低验证成本**的东西，才对 agent 需求有实质帮助：预览、清单、账本、撤销、可对账的差异。这不是"安全功能"，是**需求开关**。
- 反过来，提高模型能力但验证成本不变，需求不会涨——这就是"更强的 agent，人还是不用"的原因。
- 因此 relay 的卖点不是"AI 写回文件"，是"**AI 改的东西你能一眼核对、一键退回**"：卖的是核对成本，不是自动化。

注意别走偏：验证成本低不等于价值低。**找东西、翻译、总结**验证成本几乎为零，所以需求最大；这类方向比"替你操作电脑"更接近"用 AI 的人都要用"。如果要在两者之间选，先选验证成本低的那一侧。

一个便宜实验：同一批任务做两组，A 组有"预览 + 一键撤回"，B 组没有，看**实际使用率**（不是满意度）。使用率差多少，就是验证成本的真实价格。
