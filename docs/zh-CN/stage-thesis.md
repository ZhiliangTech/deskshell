# 阶段论：现在这一阶段是什么，下一阶段长什么样

> 状态：判断，非决定。写于 2026-11-01。用途是把"我们要做下一个阶段"从口号变成可检验的东西。
> 与 [product-shape.md](product-shape.md) 的区别：那份讲"产品长什么样"，这份讲"为什么是现在、下一阶段的结构性内容是什么"。

## 零、先分清"阶段"和"级别"（两个维度，别混）

**阶段** = 时间轴上的位置（CLI → GUI → 云 → agent → ?）。
**级别** = 影响半径（工具 → 产品 → 平台 → 基础设施 → 范式）。

两者正交：可以有一个"下一阶段级别只有 L2"的东西（新形态的小工具），也可以有一个"当前阶段级别 L4"的东西（今天的云基础设施）。

| 级别 | 判据（唯一一条） | 典型例子 | 一个人能不能发起 | 典型周期 | 该用什么指标 |
| --- | --- | --- | --- | --- | --- |
| **L1 工具** | 省一点时间 | 脚本、插件 | 能做完 | 周 | 有没有人用第二次 |
| **L2 产品** | 有人持续用、有留存、有分发 | 一个 App | 能做完，难做大 | 1–2 年 | 留存、复购、口碑 |
| **L3 平台/协议** | **别人在你上面构建** | HTTP 早期、MCP 这类接口层 | 能发起，做不完 | 3–7 年 | 第三方实现数、依赖方数量 |
| **L4 基础设施** | **别人必须先有你，才能做自己的事** | Linux、TCP/IP、CUDA、SQLite | 能发起，需要组织 | 7–15 年 | 默认集成数、被替代成本 |
| **L5 范式** | 改变了人和机器的关系，成为常识 | GUI、互联网、智能手机、LLM 本身 | 时代+资本+生态共同决定 | 15 年+ | 后代把它当空气 |

**判断级别只有一个问题：有没有一件事，是别人"本来就想做"，但"必须先有你"才能做的？**

- 有 → L3 起步；
- 没有，只是"用了更好" → 老实待在第 2 级；
- 说不清 → 说明还停在"我想做大"的层面，不是级别。

这也是为什么"级别"不能用代码量、star 数、宏大叙事衡量：**它衡量的是依赖关系，不是规模。**

一个级别的残酷之处：L4/L5 的发起者，通常要先用 L2 的方式活下来（有人用、有留存），再用 L3 的方式长大（别人依赖），最后才可能成为 L4。**跳过任何一级，都会得到一个"很有想法但没人依赖"的仓库。**

## 一、阶段的划分与规律

| 阶段 | 交互单位 | 抽象层级 | 留下的新问题 |
| --- | --- | --- | --- |
| 命令行（1970s–） | 命令 | 机器语言 | 你得知道机器怎么想 |
| GUI（1984–） | 对象/文档 | 直接操作 | 你得知道软件怎么摆 |
| 应用 + 云（2007–） | 服务/账号 | 订阅与通知 | 数据不在你手里，你看不见发生了什么 |
| 聊天助手（2022–） | 提示词 | 语言 | 它只是一次对话，不改变你的电脑 |
| **常驻智能体（2025–2026，OpenClaw 阶段）** | 委托一次任务 | 意图 | **它做了四十件事，你只看到一段话** |

规律有两条，都很稳：

1. **抽象层级不断上移**：命令 → 对象 → 服务 → 意图。每一阶段都让"你不需要懂下一层"。
2. **信任边界不断外移**：从"我操作机器"到"我信任一个进程替我做"。每外移一次，都会留下一个新的**因果不可见**问题，并由下一阶段解决。

按这条规律，OpenClaw 这一阶段留下的核心问题**不是安全，而是因果**：agent 有了系统权限、有了记忆、有了主动性，但人对"它到底做了什么、为什么这么做、能不能只退回其中一步"没有结构性的答案。安全只是因果缺失的一个后果。

## 二、下一阶段的结构性内容：从"任务"到"契约"

如果因果要被重新变成一等公民，交互单位就必须换一次：**不是"帮我做这件事"，而是"以后这类事按这个规矩办，出格了问我"**。

这在结构上等价于：**委托变成契约**（task → standing agreement）。它不是更好的助手，是另一个层级的东西。四个原语随之变化：

| 原语 | 现在（OpenClaw 阶段） | 下一阶段 |
| --- | --- | --- |
| 主体 | 一个 agent、一个身份、一个权限池 | **多主体**：你的、公司的、第三方的代理同机行动，需要身份、委托链、相互审计 |
| 信任 | 社会性的（开源、是你自己的机器、你盯着） | **结构性的**：可核查执行、效果凭据、可重放、可争议（谁授权、谁执行、谁负责） |
| 记忆 | 它的记忆，在它的目录里，格式它定 | **可迁移的个人状态**：换 agent、换机器、换模型，记忆与授权跟着人走 |
| 时间 | 现在做，做完就结束 | **长期有效**：条件、预算、例外、复议、到期——制度而不是工具 |

一句话：**上一阶段把电脑变成了同事；下一阶段要给这个同事立规矩，并且规矩本身要能被看见、被修改、被执行。**

## 三、冷水：阶段不是宣布出来的，是沉淀出来的

历史上没有人靠"宣布进入下一阶段"成功。GUI 不是从 CLI 外面长出来的，是从终端复用、位图、鼠标这些沉淀里长出来的；云不是从桌面外面长出来的，是从虚拟化、分布式存储沉淀里长出来的。**下一阶段的形态，总是由上一阶段的基础设施沉淀出原语，再由原语催生产品。**

所以有一条很硬的试金石：

> **上一阶段的产品，今天能不能直接用上你的原语？**
> 能 → 它是原语；不能 → 它是研究。

按这条尺子量：撤销、效果凭据、委托范围、预算、审批摘要——这些 OpenClaw 类产品**今天就能用**，只是它们现在没有。这符合"原语"的定义。而"语义资源视图"这类，今天没有产品能用上，所以它是研究，不能拿来当阶段主张。

另一半同样重要：**定义阶段的人，几乎都同时交出了原语和一个立刻能被感知的产品瞬间**。只交原语的人（协议作者）通常活得很久但没人记得；只交产品的人（应用作者）通常很亮但很快被替代。

## 四、三条可证伪信号（两年内）

阶段论最容易变成自我安慰，因为它没法证伪。把它压成三条可观测的现象，每季度看一次：

| 信号 | 说明 | 若出现 |
| --- | --- | --- |
| 出现"长期委托"型产品 | 卖的不是"帮你做这件事"，而是"以后这类事都按这个办"（订阅/长期授权/例外处理） | 阶段确实翻了，原语需求成立 |
| agent 之间开始互相调用、委托、结算 | 需要身份、权限链、计费与责任归属 | 多主体原语成为刚需 |
| 合规或保险开始要求 agent 行为留痕 | 金融、医疗、企业采购先出现 | 结构性信任从"加分项"变"入场券" |

三条都不出现，说明现在仍在 OpenClaw 阶段——那就要回去做能力与入口，而不是做原语。

## 五、90 天动作（如果你要押这一注）

1. **把"委托契约"抽成一个能被别人集成的层**：范围、预算、期限、例外、效果账本、撤销。不做替代 OpenClaw 的产品，做它缺的那一层。
2. **同时做一个 60 秒内能感知的瞬间**：一句话委托 → 它干了三件事 → 你说"只退回第二件" → 真的只退回第二件且逐字节一致。这个瞬间就是下一阶段的样子。
3. **把可证伪信号写进决策记录**，每季度核对一次；不出现就改判断，不硬撑。
