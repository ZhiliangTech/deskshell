# 本地智能体系统路线图

第一阶段交付现有 Windows 电脑上的本地智能体系统：“本地”指任务宿主、运行时和操作执行在用户电脑上，当前先通过云端大模型 API 理解意图并提出方案。运行时控制权限、执行、验证和恢复，桌面入口展示任务状态。长期保留本地推理适配方向，再沿这一基础向更多平台和专用设备演进。

产品方向已确定；详细工程设计见 [RFC 0001](../../rfcs/0001-local-agent-system.md)，目前为 Draft。下面各阶段是验收门槛，部分基础已经实现，不能将其等同于整个阶段完成。

[项目总入口](../../PROJECT.md) 记录已确认的愿景和产品范围，[决策登记](decisions.md) 区分已确认方向与待决事项。下述两条研究方向已确认，详细协议仍为 Draft，效果仍需实验验证。

## 当前工程基础

- 可复用 Action v0、执行内核、文件技能、Windows UIA、平台驱动工厂、CLI、MCP 和 Windows 面板。
- 已有失败断言、补偿与审计测试；最新结果和真实桌面验证范围见 [STATUS](../../STATUS.md)。
- 原有自然语言入口仍是规则解析；新 `agent` CLI 已接入常驻服务，提供照片固定计划、精确批准、组合目标验证、有条件撤销和跨进程控制；另有独立记事本任务及固定授权多轮协调器。真实 DeepSeek 加合成编辑器已完成三轮，固定原生记事本计划通过服务 IPC/宿主/驱动完整链，CRLF/LF 两次成功；本地合成规划与真实 DeepSeek 加原生三轮、四类故障及默认生产服务通过，精确配置已放行。任务/控制通道与全用户持久日预算限制授权和推理，见[文件任务](agent-file-task.md)、[多轮任务](autonomous-tasks.md)、[宿主](task-runtime.md)和[恢复](task-recovery.md)。旧三入口迁移、追问界面、自由规划及选择性恢复仍待推进。
- 当前技能是受信 TypeScript 代码，能力清单不构成第三方代码沙箱。

## 阶段与验收

| 阶段 | 核心交付 | 通过标准 |
| --- | --- | --- |
| G1 固定计划与统一入口 | 最小单用户宿主、计划/授权/执行登记、TaskService | 执行确认的同一计划；变更导致失效；并发及重启后重复提交不重复执行；模型不能自行批准 |
| G2 步骤持久化与恢复 | 步骤事件、恢复材料、资源锁、停止状态 | 关键边界退出后能核查已执行/未执行/未知；不静默重放，不覆盖外部修改 |
| G3 本地运行时上的智能体闭环 | 一个云端模型 API 适配器、观察验证、追问、有限重规划；保留未来本地适配接口 | 真实模型参与；非法输出无副作用；断网停止新推理并明确报错，本地历史、停止与恢复仍可用；取消与预算生效 |
| G4 常驻桌面产品 | 自动启动、面板、历史、恢复入口和 Windows 记事本场景 | 记事本获批工作流、窗口重建和人工操作冲突通过测试；外部用户独立完成约定任务 |
| G5 扩展与设备演进 | 第三方隔离、MCP client、跨平台与设备配置 | 隔离和副作用契约验收后再开放不可信扩展；设备形态由真实需求和性能决定 |

G1–G4 共同构成第一阶段用户产品。模型只读实验可与 G1 并行；模型触发写入必须经过已建立的计划和授权链路。macOS/Linux 现有实现保留兼容，第一阶段放行以 Windows 为准。

首个工程默认采用 DeepSeek 官方 API 的 `deepseek-flash`，见[模型接入](model-backends.md)。照片单计划最多 1 次请求、512 输出 token、30 秒和 0.01 USD 估算；应用会话默认 6 轮、可设 3–10 轮、5 分钟总时限及 0.05 USD 后端实例估算上限。两者共享 UTC 日额度 10 次/0.10 USD，重启或更换状态目录不重置。真实模型加合成编辑器三轮用量为 889/912/895 token，合计 2,696，估算 0.0038343 USD，非账单。没有自动重试；追问界面、自由规划及完整 G1–G4 尚未完成。断网停止新推理，本地记录、停止和有证据的文件恢复保持可用。

## 与 G1–G3 并行的两条研究线

协议与实验草案见 [RFC 0002 — 语义资源与效果凭据](../../rfcs/0002-semantic-resources-and-effect-receipts.md)，当前状态为 Draft。

| 研究线 | 要验证的问题 | 与交付阶段的关系 |
| --- | --- | --- |
| 主线：版本化语义资源视图 | 带稳定身份、状态版本、可用操作和来源的有限资源视图，能否改善规划与过期观察识别，先在云端模型验证，再在本地模型复现？ | 与 G1 并行定义观察和资源版本如何绑定固定计划；在 G2 验证变化与冲突；G3 建立使用原始文件/UIA 观察的真实云模型基线，本地推理对照在后续本地适配阶段独立复现。 |
| 支撑线：效果凭据和选择性恢复 | 经核验的效果记录与依赖关系，能否确定实际改动，并在不覆盖无关工作的前提下选择可安全恢复的部分？ | 与 G1 并行定义效果和凭据边界；在 G2 验证凭据、中断、冲突与恢复依赖；在 G3 向任务循环提供有依据的结果和恢复选项。 |

两条研究线不推迟首条完整任务，也不绕过其授权要求。选择性恢复必须拒绝或延后不安全的依赖组合；效果凭据不会让不可逆效果变得可撤销。

语义资源视图先通过独立于实现单测的真实云端 API 与 Windows 实验验收。效果凭据与恢复的主实验使用确定性文件、JSON 和受控 UI 场景，固定前向操作，独立于模型；模型后续参与组合后的端到端实验，再另做本地模型复现。任务、留出输入、基线和故障场景都需版本化；云端对照使用同供应商、同模型/版本、同推理参数、同底层操作、同工具权限、同预算，记录 API 版本信息、实验时间及 token、工具调用、耗时和费用上限。客户端硬件保持一致并记录，用于本地观察与执行测量，不能据此声称控制了供应商的云端算力。恢复实验还需使用同一起始状态、已执行动作与故障注入。先分别改变一个研究组件，再验证两者组合。云端结果不能直接证明小型本地模型的收益；本地复现还需控制并记录硬件、模型文件、量化与推理后端。

任务完成、过期状态/冲突识别、延迟与资源消耗、恢复成功、残留改动、对无关工作的损害分别报告。拒绝、延后和结果未知单独统计，不计作任务或恢复成功。Mock 检查证明契约行为，不能替代真实实验。研究方向获确认，不等于已经证明效果，也不等于 RFC 已 Accepted。

## 首条完整任务

用户选择目录，提出“照片按月份整理，重复内容放待确认目录，保留其它文件”。当前系统读取获准范围、展示逐文件差异、确认固定计划、执行、重读验证，并提供记录与有条件撤销；缺项目前由 CLI 参数约束，交互式追问界面仍待补齐。

冲突、人工修改、写入失败、取消和进程退出属于文件任务验收。应用阶段以真实模型加合成编辑器完成三轮；另在记事本 `11.2607.14.0` 上通过固定计划完整原生链，机器读取、中文编辑、UTF-8 无 BOM 的 CRLF/LF 精确另存和源文保留均验证。早期截图工具的 accessibility=null 是工具读取缺口。早期两次人工输入拒绝另计；后续原生合成规划三轮、真实 DeepSeek 三轮与四类故障通过，默认生产服务也已复验。真实原生三轮使用 2,543 token、估算 0.0038316 USD（非账单）。服务仅选择已放行的精确 `11.2607.14.0/zh-CN` 配置，每宿主生命周期一份文档；后续须重启并准备新计划。详见[首个应用](first-application.md)。

## 已落地基础与后续工程

1. TaskService、TaskResult、常驻文件宿主和双通道批准已落地，继续完善安装、生命周期与桌面呈现。
2. 固定计划、目标、批准、唯一认领和逐步效果已持久化，继续制定留存与磁盘配额。
3. 文件撤销和有限中断核查已支持精确批准与未知拒绝，继续验证原生并发控制和选择性恢复研究。
4. 照片按月/完整去重、全用户日预算、固定授权多轮与固定原生应用链已落地，扩展原生扰动和版本/语言/编码支持矩阵，补追问界面、自由任务规划和留出任务评估。
5. 迁移旧 CLI、Shell、MCP，通过三入口一致性、v0 兼容和真实应用验收；当前只有新 agent 入口统一到服务。

具体类型、数据边界、迁移与拟新增测试见 RFC。实现时分别记录自动夹具、云端模型、本地模型、Windows 真机和外部用户证据，不用同一个“完成”标记替代所有层级。
