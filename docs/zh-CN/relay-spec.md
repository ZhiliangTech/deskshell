# relay：AI 的输入输出总线

状态：**已有可运行的最小实现**（stub 后端，7/7 管线测试通过），真模型接缝未接。
一句话：**AI 的活落到你的文件里，做错了能退回原样。**

## 为什么不是"又一个划词问答"

豆包、系统助手、各类划词插件已经把"选中 → 问 AI → 给一段答案"做完了。再做一个更好的气泡没有意义。差别在结构，不在交互：

| | 划词问答类（含豆包） | relay |
| --- | --- | --- |
| 结果去哪 | 聊天气泡，你自己复制 | **直接写回你的文件**，走内核 |
| 出错了 | 重新问一次 | **一键退回，逐字节一致** |
| 跨厂商 | 只走自己家模型 | **后端可替换**，同一段材料可送任意模型 |
| 发了什么 | 不知道 | **外发清单**：字节数、摘要，**不含任何绝对路径** |
| 留痕 | 对话历史 | **账本**：哪一步、改了哪个文件、能不能撤 |

一句话：**气泡给你一段话，relay 给你一个能撤回的文件加一份能查的账。**

## 产品本体是四个动作，模型是第五个插槽

1. **拿材料**：文件、stdin，将来是选区/剪贴板/截图。
2. **出清单**：`backend / vendor`、字节数、sha256、指令摘要；标签只允许文件名，出现路径直接拒绝（`INVALID_LABEL`）。
3. **写回去**：走内核的 `runActions`，所以天然有账本、天然可撤销、天然受作用域约束。
4. **留账**：`deskshell undo --task <id>` 或 `--last`。
5. **模型**：`RelayBackend` 接口，`id/vendor/model + complete()`。当前只有 `stubBackend()`（确定性回显，用来验证管线）。

这五个里，前四个是产品，第五个是零件。换模型不改产品。

## 现在的实现与验证

```bash
deskshell relay --from note.md --to note.md            # 原地改写
deskshell relay --from note.md --to draft.md --dry-run # 只出清单
deskshell undo --last --root .                         # 退回上一步
```

`scripts/relay-test.ts`（7/7）：

- 清单含字节数与 sha256，且 **JSON 里不出现任何绝对路径**；
- `--dry-run` 不调用后端、不写文件（用计数后端证明）；
- 写新文件 → 账本一条 `skill=relay` → 撤销后文件消失；
- 覆盖已有文件（含 CRLF 原文）→ 撤销后**逐字节还原**；
- 空输入 / 超限输入 / 路径型标签被拒。

实测（本机）：`relay → out.md → undo` 后 `out.md` 消失，`note.md` 未被触碰。

## 接真模型只差一个方法

`packages/models/src/deepseek.ts` 里的适配器目前只有 `propose()`（面向技能提案）。接 relay 需要一个**同等的有界 `complete()`**：同样的限额、超时、取消、错误去敏、预算预留，只是输出是文本而不是提案。

接上之后 `--backend deepseek` 才有意义。**在那之前不提供这个 flag**——不提供"看起来能用但其实不通"的选项。

## 怎么验证它值得做

不是问用户"你会用吗"，而是看一个数：

> **你自己一天用它改文件几次？**

- 不到 10 次 → 它不是必经之路，方向要改；
- 10 次以上且有一次真的用了"撤回" → 这条路成立，再谈把选区/剪贴板/多模型接上。

## 60 秒分镜（要拍的那一条）

| 秒 | 画面 |
| --- | --- |
| 0–8 | Word 里一段写砸的文案，选中 |
| 8–18 | 快捷键 → 选模型 → 结果**直接替换**回文档，不是弹窗 |
| 18–28 | 屏幕角落出现清单："发送 312 字，摘要 a1b2…；已写回 3 个文件" |
| 28–40 | 点开清单：可以只撤回第 2 个文件 |
| 40–50 | 撤回，文档回到原文逐字节一致 |
| 50–60 | 账本一行："14:32 改写 第 2 段，由你批准，已撤回" |

## 与产品纪律的关系

见 [product-doctrine.md](product-doctrine.md)：**能撤回的动作不问**（写回文件属于可撤，所以 relay 默认不弹确认），**不可逆的才问一次**（覆盖被系统判定为不可逆时）。这条比"每步审批"重要得多——用户会关掉每步审批。
